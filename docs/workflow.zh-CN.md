# 从需求到成片

[English](workflow.en.md) · [返回项目](../README.md)

Prompt Motion Lab 的工作单位不是一句万能提示词，而是一份能继续实验的记录：简报、方向、双语提示词、时间分镜、场景代码、样片、验收证据和下一步。

## 1. 写简报

记录目标、观众、一句话记忆点、必须出现的事实、时长、画幅、分辨率、帧率、语言、素材和声音。非关键缺项可以自行选择并记下，例如 15 秒、16:9、三种颜色；会改变事实或授权的缺项才需要用户决定。

把“做一条很酷的视频”改成：

> 给独立开发者介绍任务管理工具，20 秒。表达“捕获 → 归类 → 今日执行”，每个镜头只讲一个操作。1920×1080，中英字幕；奶油白背景、炭黑正文、橙色强调。不创造用户评价。交付 MP4、预览、源码、分镜和实验记录。

## 2. 提出方向

至少从内容出发写出颜色、字体、材质、构图、镜头语法、内部动作、声音和实现路线。算法适合稳定几何与事件表；真实产品适合真实界面状态；动态排版适合少词大字；空间产品才需要三维层级。用户委托选择时，选一个方向并记录为什么适合目标。

## 3. 写原创双语提示词

提示词要能直接指导制作：写清每个镜头的一个主要信息、可见动作、相机、文字停留、转场、音频事件、负面规则、固定种子和验收条件。把事实与视觉隐喻分开；示意图不能冒充物理模拟。

## 4. 排时间分镜

| 时间 | 信息 | 内部动作 | 镜头 | 文字 | 声音 / 转场 |
| --- | --- | --- | --- | --- | --- |
| 0–3 秒 | 建立问题 | 主对象进入并停稳 | 全景 | 一句标题 | 起始提示音 |
| 3–8 秒 | 展示关键关系 | 事件沿路径移动 | 跟随 | 一个术语 | 动作峰值对齐 |
| 8–13 秒 | 解释变化 | 状态改变并留下痕迹 | 推近 | 参数或结果 | 内容转场 |
| 13–15 秒 | 回收结论 | 元素整理成最终形状 | 拉回 | 一句记忆点 | 收尾与停顿 |

不要把这个时序硬套到每个题目；口播先按语音段落分配时间，数据先按事实范围分配时间。重要文字至少保留足够阅读时间。

## 5. 选择实现并做样片

Canvas 2D 适合图解、粒子和像素；SVG/HTML 适合界面与排版；Three.js 适合空间层级；GLSL 适合材质与后处理。每帧由时间和固定配置计算，随机效果使用固定种子。有状态模拟要预计算或从固定初态重放。

先用自定义场景生成分镜：

    npm ci
    npm test
    npm run render -- --scene examples/custom-scene.cjs --output media/my-film.mp4 --stills-only

打开分镜，修复文字重叠、焦点不清、对象静止、转场断裂和语义错误，再渲染短样片与全片。

## 6. 让声音共享时间线

把提示音、动作峰值、口播段落和停顿放在同一张时间表。项目内置声音是代码合成配乐或音效；需要口播时使用用户录音或已获授权的 TTS，不能把音乐称为配音。

## 7. 记录状态与证据

用 draft、rendered、inspected、validated、blocked 标记状态。validated 至少需要实际画面检查、视频元数据、完整解码、叙事与可读性核对；需要确定性时重复渲染比较关键帧。记录实际观察，不用主观分数替代证据。

## 8. 导出交付

    npm run render -- --scene examples/my-scene.cjs --output media/my-film.mp4 --fps 60
    npm run build
    npm run check:media

交付 MP4、分镜、预览、源码、简报和实验记录。自定义影片按自己的尺寸、时长、帧率和音轨检查；内置 check:media 只了解两支内置影片。
